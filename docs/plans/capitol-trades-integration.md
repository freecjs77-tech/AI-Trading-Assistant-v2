## 1. 문제 정의 (Problem Statement)

마켓 스캐너 페이지에 **"Politician Watchlist" 독립 섹션**을 추가한다. 미 의회 의원들이 최근 90일간 거래한 TOP N 종목(가중 스코어 기준)을 카드 형태로 보여준다. 기존 60종목 테이블에 컬럼을 추가하는 대신, **의원 활동 자체를 주인공으로 하는 별도 섹션**으로 설계하여 "대부분 종목이 활동 없음(—)"인 데이터 희소성 문제를 구조적으로 회피한다.

기존 기술적 시그널(MA/RSI/MACD/BB/ADX)과 Master Switch 로직은 **불변경**. 의원 거래 정보는 매매 결정 로직에 개입하지 않고 리포트 열람 시 맥락으로만 제공된다.

## 2. 무엇이 매력적인가 (What Makes This Cool)

- 대중이 실시간 접근하기 어려운 STOCK Act 공시 데이터를 일일 스캐너에 자연스럽게 통합
- **"의원이 관심 있는 종목 TOP 20"** — 데이터가 존재하는 종목만 노출하므로 의미 있는 신호만 남김
- Intelligence·Armed Services 위원회 매수 같은 "위원회-섹터" 맥락을 별점 + 색상으로 한눈에 축약
- 위원회 tier 가중(비공개 브리핑 접근 위원회 2.0배) + 의원 수 임계 가점으로 **"여러 정보권 의원이 동시에 같은 방향으로 움직이는" 상황을 쉽게 포착**
- 포트폴리오 보유 종목이 watchlist에 등장하면 **기존 테이블 옆의 하이라이트 섹션**에서 한 번 더 강조 → 사용자의 기존 60종목 루틴과 자연스럽게 연결
- **Trade-off 수용**: 가중치 공식은 backtest 검증 전이라 "점수처럼 보이는" UI가 매매 결정에 인지적으로 개입할 리스크가 있다. 이를 §12 리스크로 명기하고 면책 고지로 완화.

### 5.1 스코어 공식

```
per_trade_weight = direction × committee_factor × recency_factor × size_factor
  direction        = +1 (매수) | -1 (매도)
  committee_factor = 2.0 (Tier1) | 1.5 (Tier2) | 1.0 (기타 or 미분류)
  recency_factor   = 1.0 (체결일 ≤30d) | 0.7 (30-60d) | 0.5 (60-90d)
  size_factor      = 1.3 (amount_min ≥ $500,000) | 1.0 (그 외)

ticker_raw_score = Σ per_trade_weight  (최근 90일 모든 거래 합산)

member_bonus = (매수 측) + (매도 측)
  매수 측:  distinct_buyers ≥ 5 → +2.0 | ≥ 3 → +1.0 | else 0
  매도 측:  distinct_sellers ≥ 5 → -2.0 | ≥ 3 → -1.0 | else 0

final_score = ticker_raw_score + member_bonus
```

`distinct_buyers`/`distinct_sellers`는 90일 윈도우에서 **서로 다른 의원 수** (한 의원의 복수 거래는 1로 카운트).

### 5.2 위원회 Tier

| Tier | 가중 | 위원회 | 근거 |
|---|---|---|---|
| 1 | 2.0x | Intelligence · Armed Services · Finance · Banking | 비공개 브리핑·금융 규제 접근권 |
| 2 | 1.5x | Energy · HHS · Commerce · Foreign Affairs | 섹터 친연성 높음 |
| 기타 | 1.0x | 나머지 / 미분류 / 상원/하원 동명 위원회 포함 | 기본값 |

> 의원이 복수 위원회 소속인 경우 **가장 높은 tier**를 채택 (tier max, 합산하지 않음).

### 5.3 별점 매핑 (절댓값 기준 고정 임계)

| `|final_score|` | 별 |
|---|---|
| ≥ 8.0 | ★★★★★ |
| ≥ 5.0 | ★★★★☆ |
| ≥ 3.0 | ★★★☆☆ |
| ≥ 1.5 | ★★☆☆☆ |
| ≥ 0.5 | ★☆☆☆☆ |
| < 0.5 또는 활동 없음 | — (회색 대시) |

> 임계값은 **운영 1-2개월 뒤 실제 분포를 보고 조정**한다 (§8 참조).

### 5.4 색상 규칙 (US 관례: 파랑 매수 / 빨강 매도)

| 조건 | 색상 |
|---|---|
| `final_score > 0` | 파랑 계열 (`var(--color-positive)` 류, 별 많을수록 진한 채도) |
| `final_score < 0` | 빨강 계열 (`var(--color-negative)` 류) |
| `|final_score| < 0.5` 또는 90일 내 활동 없음 | 회색 `—` |

> 한국식 색상 관례(빨강=상승)를 쓰지 않음. 미국 주식 리포트라는 맥락상 "파랑=buy 우세, 빨강=sell 우세"가 직관적.

### 5.8 색상·디자인

- `color_bias == "buy"` → 파란색 계열 (기존 리포트의 positive 색상 변수 재사용)
- `color_bias == "sell"` → 빨간색 계열 (기존 리포트의 negative 색상 변수 재사용)
- `color_bias == "neutral"` → 회색 `var(--color-border-secondary)` 대시
- 별 개수에 비례해 채도를 단계화 (★ → 연한 톤, ★★★★★ → 진한 톤). CSS 변수 파생으로 구현 (HSL lightness 조정).
- 아이콘/이모지 대신 유니코드 ★ / ☆ 사용 — 접근성 고려, 컬러 블라인드 대비로 별 개수 자체도 정보원이 되도록.

**파이프라인 통합** (C3 정정: workflow YAML을 건드리지 않고 `pipeline.py` 내부에 병합)
- `.github/workflows/daily-report.yml`은 **변경하지 않는다**. 이미 `python pipeline.py`를 실행하므로 pipeline.py 내부에 단계를 추가하면 워크플로우 자동 반영.
- `pipeline.py`에 **Step 4c "Politician Trades Aggregation"** 신설. 위치는 Step 4b(스캐너 공유 캐시 프리페치, `pipeline.py:177-203`의 `scanner_shared_{date}.json` 패턴) **직후**, 스캐너 결과 dict 렌더링(Step 5) 이전.
  1. `python politician_trades_fetcher.py` → `history/politician_trades_raw.json` 갱신 (senate/house JSON 다운로드)
  2. `python politician_trades_aggregator.py` → `history/politician_trades.json` 갱신 (90일 윈도우 집계)
- 이점: (a) 로컬 `python pipeline.py` 실행에서도 동일 흐름, (b) 기존 Telegram 실패 알림 로직에 자연스럽게 통합, (c) 스캐너 프리페치와 동일 캐싱 철학(`scanner_shared_{date}.json` 패턴) 유지.
- **별도 워크플로우 파일을 만들지 않는다**.

**인코딩**
- fetcher/aggregator 스크립트 시작부에 `sys.stdout.reconfigure(encoding="utf-8")` 적용 (Windows cp949 대응 관행)

## 6. 고려한 다른 접근 (Approaches Considered)

### A) Minimal Count — 기각
데이터 fetcher + 스캐너 테이블 1개 컬럼만 추가. 위원회 태그 없음, Highlights 섹션 없음. 3-5일 소요.
- **기각 이유**: 의원 거래 정보 대부분의 교육적 가치는 "Intelligence 위원회 의원이 반도체주 매수"처럼 위원회 맥락에 있다. 이게 없으면 그냥 raw 숫자라서 사용자에게 의미 있는 신호를 주지 못한다.

### B) Count + Committee Tag (V1 raw only) — 기각 (V2 오버라이드)
raw 수치 + 위원회 태그만 노출, 스코어·별점 없음. 인지편향 최소화.
- **기각 이유(2026-04-20)**: 사용자 요청으로 V2 스코어링으로 직접 이행. raw 수치는 별점 옆 부가 표시로 유지되므로 B의 정보량은 보존됨 (툴팁·부가 라인).

### C) Full Formula — **채택** (단 percentile calibration 생략)
계획서 원본의 trade_weight + committee_bonus + recency decay를 모두 적용하되, **고정 임계값**으로 시작 (§5.3). 운영 1-2개월 후 실제 분포 보고 임계값 조정.
- **채택 이유**: 사용자 명시적 요청 + 별점·색상이 raw 수치보다 직관적이라는 판단. 인지편향 리스크는 §12 수용 항목으로 기록, 면책 고지로 완화, §13의 V3(실질 backtest) 조건 보존.
- 원안 대비 차이점: **decile 색상 대신 "buy/sell/neutral 3색"**, **percentile 대신 고정 임계**. 구현 단순화 + 일일 분포 변동에 따라 종목 색상이 요동치는 것 방지.

## 13. ~~V2 진입 조건~~ → V3 진입 조건 (2026-04-20 재정의)

**오버라이드 기록**: 원 §13은 "V2(가중 스코어링·별점) 착수 조건" 4개를 열거했으나, 2026-04-20 사용자가 조건 4번(명시적 요청)만 근거로 V2를 즉시 착수 결정. 조건 1·2·3은 스킵. 대신 아래 조건을 **V3(실질 예측력 검증된 스코어링)** 진입 조건으로 보존.

V3는 다음이 모두 충족된 후에만 착수한다:
1. V2 운영 3개월 이상, 일일 별점 분포 · score 히스토리 로그 축적.
2. 별도 세션에서 과거 2년치 데이터로 backtest 실행, **Information Ratio > 0.3** 이상 확인.
3. 학술 논문 2편 이상 교차 검토로 "Senate 매수 시그널은 약한 양의 알파" 재확인.
4. 백테스트가 통과하지 못하면 별점을 **raw 수치 + 색상 바**로 격하하는 것도 옵션(롤백 아님, 포맷 교체).

**V3 도입 시 후보 변경 사항** (현재 스코어 공식 대비):
- 고정 임계 → percentile 기반 동적 임계 (§6 C 원안)
- 시간 decay 단일 단계 → 지수감쇠 (exp(-t/30d))
- 위원회 매핑 수동 → `unitedstates/congress-legislators` 자동
- size_factor 2-bucket → 금액 로그 스케일
